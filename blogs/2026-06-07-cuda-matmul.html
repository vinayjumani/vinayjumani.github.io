How to Optimize a CUDA Matmul Kernel for cuBLAS-like Performance: a Worklog

June 7, 2026 CUDA, Systems, HPC

In this post, I'll iteratively optimize an implementation of matrix multiplication written in CUDA. My goal is not to build a cuBLAS replacement, but to deeply understand the most important performance characteristics of the GPUs that are used for modern deep learning. This includes coalescing global memory accesses, shared memory caching, and occupancy optimizations, among others.

The Naive Implementation

Matrix multiplication on GPUs may currently be the most important algorithm that exists, considering it makes up almost all the FLOPs during the training and inference of large deep-learning models. So how much work is it to write a performant CUDA SGEMM from scratch? Let's start with a naive kernel: 

__global__ void sgemm_naive(int M, int N, int K, float alpha, const float *A, const float *B, float beta, float *C) {
    const uint x = blockIdx.x * blockDim.x + threadIdx.x;
    const uint y = blockIdx.y * blockDim.y + threadIdx.y;

    if (x < M && y < N) {
        float tmp = 0.0;
        for (int i = 0; i < K; ++i) {
            tmp += A[x * K + i] * B[i * N + y];
        }
        C[x * N + y] = alpha * tmp + beta * C[x * N + y];
    }
}

The naive implementation is straightforward but extremely memory bandwidth bound. Every thread loads a full row of A and a full column of B from global memory, resulting in terrible performance relative to theoretical peak FLOPs.

Memory Coalescing and Tiling

To improve performance, we need to minimize global memory traffic by utilizing shared memory. By breaking the computation into tiles (blocks) that fit into shared memory, we load data once from global memory and reuse it multiple times within the block.

Stay tuned as I walk through block-tiling, thread-tiling, and eventually vectorized memory accesses to reach >90% cuBLAS performance.
